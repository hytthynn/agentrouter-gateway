# ◈ AgentRouter Gateway

Локальный self-hosted шлюз к провайдеру [agentrouter.org](https://agentrouter.org) с веб-панелью
управления: пул аккаунтов, безлимитные ключи, ежедневный чек-ин ($25/день), каталог моделей и
полноценный **OpenAI-совместимый API** (`/v1`) для подключения IDE — Cline, Roo Code, Kilo Code,
Cursor, Codex CLI и любых других OpenAI-клиентов.

> Реализует ТЗ v1 (`TZ.md`): тёмно-лаймовый UI, шифрование секретов AES-256-GCM, автоматизация
> GitHub OAuth через headless-браузер Camoufox, failover-маршрутизация, per-request accounting.

---

## Возможности

| | |
|---|---|
| **Шлюз `/v1`** | `POST /v1/chat/completions` (стрим SSE + не-стрим), `GET /v1/models` — OpenAI-формат |
| **Пул аккаунтов** | Добавление по GitHub-креденшалам + system token; автоматический OAuth-вход (2FA TOTP) |
| **Авто-ключ** | При добавлении аккаунта выпускается ключ провайдера: безлимитный, бессрочный, все модели |
| **Чек-ин** | Ручной и по расписанию, с re-login-манёвром (нюанс зачисления бонуса §2.3 ТЗ) |
| **Балансы** | $ и quota с автообновлением, дельта после чек-ина |
| **Ключи шлюза** | Лимит токенов или безлимит, срок, разрешённые модели, готовые сниппеты для IDE |
| **Failover** | До 3 попыток на другой аккаунт при 401/402/403/429/5xx/WAF; trace попыток в логе |
| **Логи** | Запросы (токены, стоимость, TTFT) и системные события с ретеншном |
| **Безопасность** | Только `127.0.0.1`, AES-256-GCM для всех секретов, маскирование в логах |

## Установка

Требования: **Windows 10/11** (или *nix), **Python ≥ 3.12**, **Node ≥ 20**, [uv](https://docs.astral.sh/uv/), [pnpm](https://pnpm.io/).

```bash
# 1. Зависимости Python (создаст server/.venv)
cd server
uv sync

# 2. Зависимости и сборка UI
cd ../web
pnpm install
pnpm build          # артефакты в web/dist — их раздаёт FastAPI

# 3. Миграции БД (создаст data/app.db + мастер-ключ data/.master_key)
cd ../server
uv run agw migrate
```

### Браузер для автоматизации (нужен только для OAuth-входа)

```bash
cd server
uv run camoufox fetch    # однократная загрузка браузера (~120 МБ)
```

Без этого шага всё работает, кроме автоматизации GitHub-входа (добавление/перелогин аккаунтов).

## Запуск

```bash
cd server
uv run agw serve
```

- Приложение: **http://127.0.0.1:8787** — API + шлюз + статика UI + планировщик, один процесс.
- Dev-режим: `uv run agw serve --reload` и в `web/` — `pnpm dev` (Vite на `:5173`, прокси `/api` и `/v1`).

### Подключение IDE

На странице **«Ключи шлюза»** создайте ключ (`agw-…`) и откройте модалку «⇥ IDE» — там готовые
сниппеты. Кратко, для любого OpenAI-клиента:

```bash
export OPENAI_API_KEY=agw-...               # ключ шлюза
export OPENAI_BASE_URL=http://127.0.0.1:8787/v1
```

- **Cline / Roo / Kilo**: API Provider = OpenAI Compatible, Base URL `http://127.0.0.1:8787/v1`.
- **Cursor**: Override OpenAI Base URL + ключ, модель добавить вручную.
- **Codex CLI**: `~/.codex/config.toml` с `base_url = "http://127.0.0.1:8787/v1"` (сниппет в UI).

## Первые шаги в UI

1. **Аккаунты → + Добавить аккаунт**: GitHub-логин, пароль, **TOTP-секрет** (base32 из настроек
   2FA GitHub) и **system access token** (консоль AgentRouter → «Системный токен доступа»).
   Автоматизация выполнит OAuth-вход headless-браузером, проверит токен, выпустит безлимитный
   ключ и синхронизирует модели. Прогресс виден в реальном времени (SSE).
2. Если GitHub запросит код из письма (device verification) — модалка примет код у вас.
3. **Модели**: включите нужные модели каталога — они появятся в `/v1/models` шлюза.
4. **Ключи шлюза**: создайте ключ, подключите IDE.
5. **Настройки**: время чек-ина (09:00 ± 0–15 мин джиттера), стратегия роутинга, ручной запуск джоб.

## Конфигурация

`.env` (см. [.env.example](.env.example)) — окружение приложения:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AGW_HOST` / `AGW_PORT` | `127.0.0.1` / `8787` | адрес сервера. **Не выставляйте наружу** |
| `AGW_DATA_DIR` | `<репозиторий>/data` | БД, мастер-ключ, storage-state, логи |
| `AGW_MASTER_KEY` | файл `data/.master_key` | мастер-ключ шифрования (env имеет приоритет) |
| `AGW_LOG_LEVEL` | `INFO` | уровень логирования |

Runtime-настройки (перекрывают дефолты, меняются без рестарта из UI): стратегия роутинга,
`checkin_daily_at`, периоды джоб, client-профиль WAF-имперсонации, лимиты параллелизма,
ретеншн логов.

## Безопасность

- Сервер слушает **только `127.0.0.1`**; CORS — localhost-источники. `/api/*` без пароля —
  это зона локального доверия (master-PIN — Phase 2).
- Секреты (пароль GitHub, TOTP-секрет, system token, ключи `sk-…`, `agw-…`, сессии) хранятся в
  SQLite **только в шифрованном виде**: AES-256-GCM, формат `v1:<nonce>:<ciphertext>`, AAD = имя
  поля. Проверка: открыть `data/app.db` любым SQLite-браузером — поля нечитаемы.
- Мастер-ключ — `data/.master_key` (32 байта, создаётся при первом запуске) либо `AGW_MASTER_KEY`.
  **Потеря мастер-ключа = аккаунты придётся добавить заново** (расшифровка невозможна).
- `data/` в `.gitignore`; ни один секрет не попадает в git.
- Промпты и ответы моделей **не сохраняются** — только метаданные запроса.
- В логах и ошибках секреты маскируются (`sk-***`, `agw-***`, `Bearer ***`).

### Что лежит в `data/`

```
data/
├─ app.db          # SQLite (WAL) — вся БД
├─ .master_key     # мастер-ключ шифрования (0600)
├─ states/         # storage-state браузера + last_error.png скриншоты
└─ logs/app.log    # файловый лог приложения (ротация 5 МБ × 5)
```

## Обход WAF и профили клиентов

Транспорт к agentrouter.org — **curl_cffi** с TLS-имперсонацией Chrome (§10 ТЗ). Client-профили
(`codex`, `claude-code`, `zcode`, `kilo-code`, `cline`, `browser`) задают User-Agent и заголовки
апстрим-запросов; они редактируются в **Настройках** без пересборки.

Если WAF начал блокировать (`waf_blocked` в диагностике):
1. Запустите **«⚡ Диагностика»** на карточке аккаунта — она прогонит каждый профиль через
   `GET /v1/models` и покажет вердикт `ok / waf_block / auth_error`.
2. Смените `default_client_profile` в настройках на профиль с вердиктом `ok`.
3. При необходимости обновите отпечаток: `uv sync` (новая версия curl_cffi) и/или поправьте
   UA-строку профиля в настройках.

## Чек-ин: как это работает

- POST `/api/user/checkin` (кандидаты `/api/user/check_in`, `/api/user/sign_in` перебираются,
  рабочий путь кэшируется).
- **Нюанс провайдера**: бонус зачисляется только после выхода и повторного входа — после
  успешного чек-ина приложение делает re-login через сохранённую сессию и заново читает баланс.
  Если сессии нет — бонус придёт при следующем перелогине (в логе будет предупреждение).
- «Уже чекинились сегодня» — не ошибка (info-лог).

## FAQ

**Забыл/потерял `data/.master_key`.** Аккаунты не расшифровать — удалите `data/app.db` и
`data/.master_key`, запустите `uv run agw migrate` и добавьте аккаунты заново.

**Порт 8787 занят.** `AGW_PORT=8788 uv run agw serve` (или `--port`).

**WAF блокирует, `waf_blocked` в ошибках.** См. раздел «Обход WAF»: диагностика → смена профиля.

**`Budget pool quota has been exhausted` (402).** Дневной пул модели у провайдера исчерпан;
пополнения в **02:00 и 11:00 UTC**. Шлюз сам попробует другой аккаунт; при исчерпании всех —
вернёт ошибку с подсказкой.

**GitHub требует код из письма.** Введите его в модалке прогресса (окно 5 минут). Storage-state
кэшируется — при следующих входах верификация обычно не запрашивается.

**Аккаунт помечен «нужен перелогин».** Токен/сессия отклонены (401). Нажмите «↻ перелогин».

**Группа `probation`.** Провайдер перевёл аккаунт в тариф ×2 за «неподдерживаемый клиент» —
бейдж-предупреждение на карточке; такие аккаунты идут последними в роутинге.
